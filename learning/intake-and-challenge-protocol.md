# Learn the system before trying to repair it

## Purpose

Use this protocol when entering a new operation or encountering a new recurring problem. It preserves the clean reference model while giving local practice a fair hearing.

## The loop

```text
Observe actual work → state the reference expectation → identify the gap
     ↑                                                    ↓
measure consequence ← test the local rationale ← ask why the gap exists
```

## First-contact intake

Ask, before offering a solution:

1. What outcome is the process meant to create, for whom, and to what acceptance criterion?
2. Where does work physically and digitally begin and end?
3. What is normal work? Ask to see the standard, then observe actual work.
4. What fails most often, costs the most, or creates the most waiting and rework?
5. What are people already doing to make the system work despite itself?
6. Which measures are trusted, which are merely reported, and who owns each definition?
7. What changes have already been attempted? What happened afterward?
8. What constraints are real: safety, customer/regulatory, engineering, capacity, union/work rules, supplier, budget, or technical?

## Reference-versus-reality discipline

For every apparent gap, write three statements:

- **Reference:** What the clean model would ordinarily expect.
- **Observed reality:** What happens, where, when, and how often.
- **Local rationale:** Why knowledgeable people believe the deviation exists.

Then classify it:

| Classification | Response |
|---|---|
| Necessary adaptation | Preserve it; document the constraint and review trigger. |
| Unmeasured workaround | Measure its load and failure modes. |
| Historical scar | Test whether the original constraint remains. |
| Deliberate tradeoff | Make the cost/benefit explicit and owned. |
| Likely defect | Contain, investigate, and improve. |

Never equate “different from the corpus” with “wrong.” Never let “we have always done it this way” substitute for a rationale.
