## Objective

Keep DigitalIE safe to extend while it remains Markdown-first and private. New operational experience must be attributable, scoped, reviewable, reversible, and unable to promote itself into baseline guidance.

## Active sequence

### 1. Staged metadata enforcement

The metadata schema exists, but most baseline documents do not yet carry machine-validated metadata. Select one content class, apply the contract consistently, resolve migration defects, and only then enable its CI gate. Do not claim repository-wide metadata conformance before the rollout is complete.

**Done when:** enforced files validate `id`, class/type, status, scope, source class, owner, review date, supersession, and relationships; IDs are stable and globally unique.

### 2. Agent evaluation coverage

Current synthetic fixtures exercise exception, recovery, decision-intelligence, capability-factory, and industrialization failure modes. Readiness, conformance, change-impact, and reliability agents still lack direct fixtures, and no card yet has the full normal, missing-data, and authority-pressure set.

**Done when:** every agent card links at least one fixture in each required class, critic conflict is represented, and evaluation checks fail when evidence or authority behavior regresses.

### 3. Generated navigation and coverage

Indexes are hand-maintained. Generate a read-only catalog from validated metadata after the first metadata class is conformant. Markdown remains canonical; generated views must identify their source revision and never become a second editing surface.

**Done when:** orphaned entries, duplicate IDs, missing relationships, stale reviews, and process/agent/evaluation coverage are reported with exact repair targets.

### 4. End-to-end process exercises

Exercise the nine process contracts against synthetic cases that cross process boundaries. Prioritize handoffs where identity, configuration, authority, evidence, or status can be lost. Record ambiguity as a contract defect, not as narrative explanation.

**Done when:** each process has a traceable intake-to-handoff example and the receiving process can continue without reconstructing scope or authority.

### 5. Calculation-pack assurance

The Calculation MCP is the first implemented portal. Continue independent golden-case verification, boundary/rejection coverage, receipt compatibility checks, and documentation-to-code reconciliation as methods change. Add manifest-schema enforcement before treating the portal definition as machine-governed.

**Done when:** every method meets the calculation-pack standard, registry discovery is reproducible, and a version change cannot silently alter prior receipts.

### 6. Use-based corpus review

Review new observations, candidate promotions, source dates, duplicate concepts, unused artifacts, agent-evaluation failures, and calculation incidents on a defined cadence. Remove or merge material that does not improve a decision.

**Done when:** review decisions identify owner, evidence, disposition, affected scope, and next review date.

## Deferred until evidence justifies them

- PostgreSQL case-management service and write-capable MCP tools
- Embeddings, graph retrieval, or automatic context injection
- Runtime process agents and plant-system integrations
- A golden agent-ready repository generalized from fewer than two observed implementations
- Universal autonomy/risk tiers guessed without workflow consequence data

## Standing non-goals

- No employer operational data in this repository.
- No automatic promotion from observation, AI output, or a single case.
- No model/provider benchmarking unless it supports a defined manufacturing workflow decision.
- No new playbook family until recurring use exposes a missing decision route, evidence contract, or competent critic.
