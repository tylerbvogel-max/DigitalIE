# Software factories

## Question answered

How can repeated demand become a governed flow that reliably produces verified software capabilities rather than bespoke agent sessions?

## Factory flow

`demand → triage → reusable pattern selection → bounded build → automated verification → independent review → release gate → deployment → telemetry → learning`

Standardize the production system: repository template, architecture views, secure defaults, environment provisioning, CI/CD, test/eval harness, observability, release/rollback, documentation, ownership, and retirement. Preserve variation where the business problem requires it; eliminate accidental variation in delivery mechanics.

## Control rules

- Define product families and reusable modules before measuring throughput.
- Treat prompts, skills, tool schemas, models, policies, and evals as versioned configuration items.
- Separate build agents, critics, release authority, and production credentials.
- Promote through evidence gates; never equate generated code with accepted code.
- Measure accepted lead time, escaped defect, rework, recovery, reuse, outcome value, and cost—not lines or agent tasks.

## Output

Reference pipeline, golden repository, capability catalog, quality/security gates, deployment/rollback contract, operational telemetry, and learning backlog.
