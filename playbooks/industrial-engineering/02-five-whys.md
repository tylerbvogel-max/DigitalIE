# 5 Why: build a testable causal chain

## Best use

Use for a specific, repeatable effect with a bounded process. Branch the chain if the evidence points to more than one mechanism.

## Procedure

1. Put the verified effect at the top—not a cause-shaped statement.
2. Ask what mechanism immediately produced it.
3. For every proposed answer, record evidence, confidence, counterexamples, and the test that could disprove it.
4. Continue only while the next link is observable or testable.
5. Stop when the team reaches a controllable process condition, standard, design decision, or system constraint.

## Failure modes

- “Operator error” ends inquiry instead of explaining the work condition.
- Five is treated as a required number.
- A chain becomes linear when mechanisms should branch.
- A plausible answer is accepted without a discriminating test.

## Exit

The result is a causal hypothesis map and a validation plan. Only validated links may support a corrective action.
